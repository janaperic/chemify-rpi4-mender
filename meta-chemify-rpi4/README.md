# meta-chemify-rpi4

Integration layer for Mender on the Raspberry Pi 4 Model B (Yocto Project Scarthgap).
`kas/chemify-rpi4-mender.yml` adds it to the build. kas fetches all other layers.

| Path | Purpose |
|---|---|
| `conf/layer.conf` | Layer definition (collection `chemify-rpi4`, priority 20, compatible with `scarthgap`) |
| `recipes-mender/mender/mender_%.bbappend` | Installs the Artifact verification key as `/etc/mender/artifact-verify-key.pem`. meta-mender then sets `ArtifactVerifyKey` in `/etc/mender/mender.conf` automatically |
| `recipes-mender/mender/files/artifact-verify-key.pem` | **Temporary development public key** (RSA 3072), generated by Northern.tech for validation (SoW R.1.4). Its private key is not part of this delivery: replace this file with your own public key before your first build (see `docs/01-integration-guide.md`, section 9.2) |
| `classes/mender-raw-extra-parts.bbclass` | Removes the `/etc/fstab` entry and the mount directory that meta-mender creates for each extra partition, for the partitions listed in `MENDER_RAW_EXTRA_PARTS` (here: the raw `secrets` partition, `/dev/mmcblk0p6`). Enabled with `IMAGE_CLASSES += "mender-raw-extra-parts"` in `kas/chemify-rpi4-mender.yml`; see `docs/01-integration-guide.md`, section 1.2 |
| `recipes-devtools/pseudo/` | Backport of the `pseudo` recipe (version 1.9.11), see below |

## pseudo backport

`recipes-devtools/pseudo/` is an unchanged copy from openembedded-core, branch `scarthgap`, at commit
`d40b840d5c7e7b0f9e94c2b434010fb63b306a72`. The last change to the recipe there is `2d50a4b127`
("pseudo: 1.9.10 -> 1.9.11").

**Why:** current Ubuntu 24.04 host `tar` packages (observed with `1.35+dfsg-3ubuntu0.4`) create
directories with the `openat2()` system call. The pseudo version in yocto-5.0.15 (1.9.0+git) does not
intercept `openat2()`, so `do_package` of arbitrary recipes fails with errors such as:

```text
got *at() syscall for unknown directory, fd 4
unknown base path for fd 4, path share
```

The fix (oe-core commit `f24e702b80`, "pseudo: Add in openat2, exec and linkat fixes") is included in
yocto-5.0.21 and later.

**When to remove:** once `openembedded-core` is pinned to yocto-5.0.21 or later, delete
`recipes-devtools/pseudo/` from this layer.
